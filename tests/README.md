# tests — 验收测试与样例数据

测试风格：不是框架里的 `unittest`，而是**逐条打印「期望 / 实际」的断言脚本**，
全过退出码 0，有失败退出码 1，可以直接挂进脚本。

## 文件

| 文件 | 覆盖 | 项数 |
|---|---|---|
| `test_simc.py` | 解析 / 查库 / 换算 / 宝石附魔 / 自选 / 孔位 / 导出 / 插件 | 287 项 |
| `test_accounts.py` | 注册登录 / 历史去重 / 存档 / 越权 | 40 项 |
| `demo_profile.txt` | 样例导出（真实数据，角色名/服务器已脱敏），**入库** | 样例 |
| `my_profile.txt` | 本机真实导出（含角色名/服务器，**不进版本库**） | 私用 |
| `sample_profile.txt` | 构造的回归样例（含故意不存在的装备） | 样例 |

## 运行

```bash
python main.py --test              # 跑两个测试
python tests/test_simc.py          # 单独跑
python tests/test_accounts.py
```

## 测试分组（`test_simc.py`）

- **group_parse**：纯字符串，验证 SimC 格式的各种写法（逗号、`gem_id=0`、`### Gear from Bags ###`）
- **group_db**：装备 id 对照数据库，验证命中与各类告警
- **group_e2e**：用样例 profile 跑完整流程，核对属性合计
- **group_real**：真实角色导出的完整校验（有 `my_profile.txt` 才跑）
- **group_tiers**：套装转化追踪
- **group_gems_enchants**：宝石附魔进计算（单颗值、合计、换装继承）
- **group_customize**：自选（换/拔/越界/撤销宝石、跨部位附魔、导出跟随、选项列表）
- **group_panel**：面板按「职业:专精」分存（换专精不继承、各专精互不影响、老格式自动迁移）
- **group_gem_slots**：孔位位置（拔中间孔不移位、空孔导出成 `gem_id=0`）、
  预览不落地、宝石带装等与中文名、附魔覆盖部位、打孔器开孔（孔数只加一次、
  有宝石不能撤孔、只有头腰腕能开、额外孔不写进 simc）、腿部附魔、主属性附魔落到职业属性、
  导出保留插件头与 adler32 校验和、导出再导入的往返、拔一颗孔还在、唯一宝石每人一颗
- **group_curves**：绿字换算。锚点是无 buff 守护德面板（暴击 1010=31.96%、
  急速 1294=30.70%、全能 419=19.76%、精通 252=13.63%），验证递减档位和每专精精通系数。
  注意这是「数据 → 模型 → 对上面板」，不是拿面板去调常数
- **group_update**：版本清单。只测离线逻辑（版本号比较、清单结构），不打网络

## 测试原则

最容易出的错不是"算错"，而是**"改了没生效"**或**"生效了但撤不掉"**——前者会让人
以为功能没做，后者会让人不敢用。所以 `group_customize` 专门盯着这几个动作来回验证。

`group_gem_slots` 盯的是另一类："看着没坏其实不对"。拔中间那颗孔、后面的宝石顶上来，
数值完全没错，但位置错了、导出的 simc 也错；预览如果落了地，用户鼠标划一圈就改掉了
配装。这类错不会报异常，只能靠测试抓。

## 样例文件

- `demo_profile.txt` 是**入库的样例**，内容和真实导出一模一样，只是把角色名换成了
  `Demo`、服务器换成 `Example`。`python main.py` 和网页的「用样例试试」都优先用它，
  克隆下来立刻能看效果。它故意删掉了结尾的 `# Checksum`——改过角色名的文本本来就
  不可能和插件原值对上，留着反而是个错的值。
- `my_profile.txt` 是本机真实角色的 `/simc` 导出，含角色名和服务器，**在 `.gitignore` 里**。
  有它的时候优先用它（数据最真实），`group_real` 也只在有它时才跑。
- `sample_profile.txt` 是构造的，**入库**，故意塞了几件不存在的装备，用来验证告警路径。

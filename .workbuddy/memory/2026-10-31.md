# 2026-10-31

## 第十七轮：专精基线表（解决「换职业就错」）

### 起因
用户质疑：现在只有拿对应角色的数据才能算准，换职业就错，"核心卖点是属性计算，算不准没人用"。
问 Raidbots 怎么解决。附带给了生存猎人两张面板截图（换了一件装备）。

### 查 SimC 源码的结论（重要，推翻了一个常见误解）
- SimC 有 40 个专精子类，但**属性换算一行都不在里面**。`composite_spell_crit_chance()`
  在 `player.cpp` 基类，40 专精共用，结构是「基础值 + 评级换算 + buff」，没有 switch(spec)。
- 专精差异只有两个维度：①`_mastery = find_mastery_spell(spec)->effectN(1)` 一个查表指针
  ②`get_passive_player_value()` 扫被动累加。**用数据表达差异，不用代码表达**。
- 所以我们的答案：不建 40 个类，建一张表。40 个类意味着改一处公式动 40 处，必然分叉。

### 关键数据（全部来自客户端，不是拟合）
- `engine/dbc/generated/sc_scale_data.inc` 里 `__combat_ratings[24][90]`：
  暴击/精通 46、急速 44、全能 54、吸血 69、闪避 36.8。90 级值 ×100 = 项目里的 base_rate，
  **完全一致**——Maxroll 那份数据其实就是这张表，不是二手拟合。
- 精通系数取法：`spelleffect_data_t::mastery_value()` = `_sp_coeff * 0.01`（第 11 个字段），
  必须 index 0。`专精精通系数表.md` 的取法是对的。
- `dbc::all_crit_base()` 直接 `return 0.05`（注释 "Gametables removed in Legion"）——
  唯一一个不查表不扫被动就确定存在的基础百分比。
- Aura 映射（扫被动时要用）：`A_MOD_ALL_CRIT_CHANCE=290`、`A_MOD_VERSATILITY_PCT=417`、
  `A_MOD_MASTERY_PCT=318`。原料 `__spelleffect_data[53449]` 就在 sc_spell_data.inc 里。
- SimC 数据里**没有** CurvePoint 表（DR 曲线 21024 是 hotfix 数据），也没有
  oct_class_combat_rating_scalar（新版已删）。

### 两张截图的验证（决定性）
生存猎人，风换一件装备：暴击 1033→1084（+51）、精通 1636→1585（−51）、急速/全能不变。
- Δ 法直接定分母：51 评级 / 1.11% = 45.95 → **暴击分母 46 确认**，不依赖任何假设
- 反推基线：crit 15.003/15.005、haste 2.044/2.044、vers −1.004/−1.004、
  mastery 14.003/14.001，**漂移 ≤0.002**（面板两位小数的舍入极限）
- **精通必须走递减**：不打折时基线漂 0.109，加上 1380 那档后收敛到 0.002。
  这把 Maxroll 的 DR 表也验了——之前以为"装备没进递减区，验不出来"，其实 1636 已经进去了。
- 反推的精通点数全是整数：射击/敏锐 8 点（=客户端基础值，没吃天赋），
  兽王 11、生存/守护 14（多的是天赋）。

### 改动
- 新增 `data/raw/spec_stats.json`：5 个专精的基线（命中/急速/精通/全能）+ source + confidence。
  `confidence: low` 的标注了可疑点（守护德精通按 coeff 1.0 算出来是 8.15 不是 9.8）。
- `build_db.py`：新建 `spec_stats` 表；`load_spec_stats()` 比对文件里的 build 和 meta.json 的
  wowBuild，不一致打警告（观测值的失效方式不是"有新版本"而是"天赋改版"）。
- `session.py` 三处：
  1. `_curve_pct` 去掉 `+ mastery_base_points(8)`（全局常数，实测每专精不同）
  2. 新增 `spec_base()` 查表、`flat_source()` 报来路（panel/spec/base/none）
  3. `flat_pct()` = 表铺底 + 面板逐项覆盖；没数据的专精补 5% 基础暴击（`CRIT_BASE_PCT`）
- `set_panel()` 补 `self._flat = self.flat_pct()`——**原来漏了，填完面板百分比纹丝不动**。
- 前端 `render.js`：百分比悬停显示「装备 23.15% ＋ 天赋 15.00%」，CSS 加 `cursor:help` + 虚下划线。
- 文档：data/README 加 spec_stats 性质说明、技术路线改「第三层」整段（含验证过程）、
  wowlib/README 加公式与 flat_source 四态表、build/README 说明它为什么不在版本清单里。
- 测试 254→**260 项**，新增 `group_spec_base()`：表入库、没面板用表、面板逐项覆盖、
  换装备基线不变、精通必须走递减、没数据的专精只补 5% 暴击。

### 遗留
- 只有 5 个专精有基线（猎人三系 + 敏锐 + 守护），35 个没有。两条路：
  ①扫被动（原料齐全，要判 spell 的 class_mask/spec 归属，工作量大）
  ②用户填面板逐步积累（表 + 覆盖的架构已支持）
- 生存 vers −1.00、射击 vers −0.55 反常（不像整数的天赋加成），疑采样时有 buff，待复核。
- 守护德精通系数到底该 0.7 还是 1.0（面板显示的是攻强那条），`spec_mastery.json` 里有矛盾记录。

## 第十八轮：朋友测试前的体验打磨

### 用户决定
不扫被动了，"把现在能做好的做好"，准备把测试版给朋友测各自职业。所以重点不是补数据，
而是**别让朋友被不完整的数字误导**——他导入自己的角色看到暴击 12.74% 而游戏是 20%，
会认为工具不准，这是最容易失去信任的地方。

### 抓到的问题
`renderStats()` 里的 `calibrated = !!Object.keys(s.panel).length` —— **只看"填没填面板"**。
只填了敏捷/耐力、没填百分比的情况下，界面显示"面板值 / 含角色基础"，
但绿字四项仍然是「只算装备 + 5% 暴击」，**界面上一个字都没提**。朋友测必踩。

### 改动
- `render.js`：`calibrated` 旁边加 `pctThin`，逐项看 `flat_source !== "panel"`。
  缺天赋的那项百分比后加金色小星号 `<i class="est">*</i>`，属性栏底部加一行
  「* 绿字只算装备，填「面板校准」可补上天赋」。
  有数据的专精不显示星号（兽王四项无标记，战士四项全带），填了面板星号消失——
  这是给用户的正向反馈。
- 主行文案去重：`职业基础/未含天赋，可校准` → `职业基础值 / 主属性未含天赋`，
  和星号行的"绿字"分工，不重复说同一件事。
- `index.html`：面板校准弹层里百分比那段说明过时了（还写"影响换算率"），
  改成"建议四项都填，不填只能套用专精默认值，你的天赋点法跟别人不一样就会差几个百分点，
  属性栏带 * 的就是这种情况"——和界面上的星号形成闭环。
- `src/web/README.md` 新增「属性栏：数字不全时要看得出来」一节。
- 确认内测包没问题：`package_beta.py` 带 `data/wowgear.db`，`spec_stats` 表就在库里；
  `data/raw/` 不带但运行时不需要（只 build 时读）。

### 验证
- 测试 260 + 40 全过（前端改动不影响 Python 测试）
- 截图对比：战士（无数据）四项带星号 + 两行说明；兽王（已校准）无星号 + "校准值/含角色基础"
- 悬停 HTML 抓取确认：`装备 23.15% ＋ 天赋（面板反推）15.00%`

## 第二轮：simc 解析（命令行）

### 交付
- `src/wowconst.py`：职业表/槽位表从 `serve.py` 抽出共享，避免两处定义漂移
- `src/simc.py`：解析 + 查库校验 + 报告 + JSON 输出 + `--selftest`（10 项，全通过）
- `tests/sample_profile.txt`：战士样例，故意含一件库里没有的装备验证缺失分支

### 解析层踩到的三个坑
1. **名字含逗号**：不能按逗号粗暴切，要用「逗号后紧跟 `键=`」切分（`re.split(r",(?=[A-Za-z_0-9]+=)")`）
2. **字段值要按列表存**：`bonus_id` 会重复出现，先收 list 再合并；早期写成 dict 覆盖会丢数据
3. **BOM**：`\ufeff` 会让第一行的键变成 `\ufeffwarrior`，必须 `lstrip("\ufeff")`

### 语义层踩到的三个坑（比解析重要）
1. **主属性多形态**：`力量/智力`（stat_id 71-74）是"按职业自适应"，只出其中一个；且部分装备同时挂力量和智力两行，全加会虚高一倍 → 按 `职业+专精` 收成一个（`SPEC_PRIMARY` 表处理神圣骑士/元素萨满这类歧义）
2. **制造业自选槽**（stat_id 24/25）：alloc 是整块预算（17000 这种），不是属性值，显示成 `+自选×N`，不计入合计
3. **装等绝不能回退到 `raw_ilevel`**：那是裸机装等（S2 团本记作 219），和面板差几十级。只认 simc 的 `ilevel=` 或 `bonus_id` 反查 `ilevel_tracks`

### 属性公式（已在 SimC 源码确认，待校准）
`属性 = alloc × item_budget(装等, 品质, 部位) × 0.0001`，战斗等级属性再过 `apply_combat_rating_multiplier`
- `item_budget` 来自 `RandPropPoints`，可从 `https://wago.tools/db2/RandPropPoints/csv` 取（ID=装等，`EpicF_0..4` 五档部位系数，比例约 1 : 0.75 : 0.5625 : 0.5 : 0.5）
- **卡点**：部位索引对应关系 + 战斗等级倍率还需一次真实面板校准，不校准不敢报绝对数值

### 下一步
等用户提供真实 simc 字符串 + 游戏内角色面板（主属性/耐力/暴击/急速/精通/全能 的数值与百分比），用面板反推校准预算曲线。

## 第六轮：套装转化追踪 + 属性公式定了

### 机制（用户告知，数据验证成立）
本赛季装备可催化转化成套装件，**绿字原样保留**。所以套装件自身属性表不可信，
`redirected_base_stats` 就是源装备 id。用户 5 件套装件（头/肩/胸/手/脚，category=catalyst，set=2059）全部对上。

### 交付
- `src/tiers.py`：正向（profile → 源装备）+ 反向（绿字占比 → 当前赛季最接近的可转化源）
  - 源可能是老资料片装备（239035 是 BfA），库里没有 → 回原始数据；比较时必须用**占比**，不同装备预算不同
  - 命令：`--profile` / `--slot head --list` / `--slot head --stats crit,mastery`
- `simc.py` resolve 增加"套装转化件"标注
- 测试 80 → **86 项**

### 属性公式基本确定（用用户面板反推）
| 类别 | 倍率 | 验证 |
|---|---|---|
| 暴击/急速/精通/全能 | **1.0** | 暴击算出 1067.7 vs 面板 1065，差 0.2% |
| 主属性 | ≈1.23 | 2318 vs 2861，差值疑似来自未计入的宝石附魔 |
| 耐力 | ≈11.8 | 3620 vs 42612 |

即 `评级 = alloc × EpicF(装等, 部位档位) × 0.0001`，次要属性无额外倍率。
部位档位映射：头/胸/腿/主手=0，肩/手/腰/脚=1，腕/背/颈/指/饰品=2。

### 重大发现：crafted_stats 不可信
导出写 `49/36`（精通/急速），用户口述实际是**全能精通**。按导出算 → 急速虚高 400+、全能少一半。
代入真实属性后，战斗等级倍率立刻从 1.05~1.09 收敛到 1.0。
**结论：制造业/装绑的自定义属性必须用户指定**（制造业两属性平分，装绑一大一小）。

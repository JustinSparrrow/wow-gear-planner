# 魔兽装备规划器

给角色做装备规划的工具。核心问题是：**Raidbots 能告诉你现在的装备有多强，但算不出
"如果换成那件，我的属性会变成什么样"**。

粘一份 `/simc` 导出进来，就能在本地预览换装、插宝石、附魔之后的面板，最后导出回 simc
丢给 Raidbots 跑模拟。**运行时完全离线**，只有抓数据那几步要联网。

## 快速开始

只要有 Python 3.10+，**没有第三方依赖**，不用装任何东西。

```bash
git clone https://github.com/JustinSparrrow/wow-gear-planner.git
cd wow-gear-planner
python main.py                 # 交互式，载入自带的样例角色
python main.py --web           # 网页界面 http://127.0.0.1:8765
python main.py 你的导出.txt     # 换成自己的 /simc 导出
```

仓库里带了建好的 `data/wowgear.db`（5MB）和一份**脱敏的样例导出**
（`tests/demo_profile.txt`，角色名和服务器换成了 Demo/Example）。
所以 clone 完直接就能跑，不用先下 61MB 原料、也不用建库。

想看自己的角色：游戏里输入 `/simc` 复制全文，存成 txt 丢给 `main.py`；
或者 `--web` 之后粘进导入框。

### 数据过期了（换赛季 / 换补丁）

```bash
python main.py --check-update   # 对比 wago 上的最新 build，看哪些数据集过期
python main.py --update         # 只重拉过期的那几份，然后重建库
```

要完整重建，得先有原料（61MB，不入库）：

```bash
python src/build/fetch_static.py   # 拉 Raidbots 静态数据（可加 --proxy）
python main.py --build             # 从 data/raw 建库，约 10 秒
```

> 为什么自带的库要入库：重建一次要先拉 61MB 再跑十几秒，别人只是想试一下的话
> 成本太高。代价是每次 `--build` 都会改这个文件，提交时留意别看花眼。

### 其它命令

```bash
python main.py --test    # 验收测试，287 + 40 项
python main.py --size    # 看各处占了多少空间，哪些能删
```

交互式里能做的事：

```
s <部位>   换装备，如 s head / s finger1 / s main_hand
stat       每件装备各贡献了多少属性
fix        确认制造业/装绑的自选属性（改完自动记住）
lookup     查装绑 / 制造业在指定装等下的绿字
tiers      套装转化追踪（看套装件来自哪件源装备）
export     导出当前配装为 simc 字符串
web        启动网页界面
```

**换装是临时预览再确认**：选中装备后先算出新的属性合计并显示增减，按 `y` 才真正换上。

想发给别人试用就打内测包（只有运行时需要的东西，**不带** `data/raw`、账号库、
你自己的面板校准和真实 simc 导出）：

```bash
python tools/package_beta.py        # 产出 dist/魔兽装备规划器-内测版-v<版本>.zip
```

## 版本更新：换数据，不重做项目

项目里三层东西，混在一起就会"越补越乱"：

| 层 | 是什么 | 版本更新时 |
|---|---|---|
| **引擎** | 怎么算属性、怎么导出 simc、界面 | **不动**。代码里没有一个游戏数值 |
| **数据集** | 装备表、中文名、宝石附魔、换算率、精通系数 | 只重拉这几份 `data/*.json` |
| **角色状态** | `panel.json` 面板、`accounts.db` 存档 | **不动**，除非你自己换了装备/天赋 |

新赛季不需要重做：代码一行不改，只刷新数据。

```bash
python main.py --check-update    # 看哪些数据集过期
python main.py --update          # 只重拉过期的，然后重建库
```

```
最新零售 build：12.1.7.70668
数据集                 本地            最新        更新时间     状态
装备 / 副本 / 赛季  12.1.5.70575   12.1.7.70668  2026-10-27   ✓
绿字换算 / 递减     12.0.1.63000   12.1.7.70668  2026-10-31   ⚠ 过期
```

**判断标准是「大版本」**（`12.1` vs `12.2`）：12.1.5 → 12.1.7 这种小补丁，装备数据通常还能用，
只会少几件新装备，标 `✓`；跨大版本才标 `⚠`。这条规则在 `versions.major()` 里。

哪些自动、哪些要人看：

| 数据集 | 刷新方式 |
|---|---|
| 装备 / 副本 / 赛季 | `fetch_static.py` 从 Raidbots 拉 |
| 物品中文名 | `fetch_names.py`（自动读 `meta.json` 的 build 号） |
| 宝石 / 附魔 / 孔位 | `fetch_gems_enchants.py` / `fetch_sockets.py` |
| 裸装基础属性 | `fetch_class_base.py` |
| 专精精通系数 / 绿字换算 | **人工核对**（客户端法术表 / Maxroll） |

⚠️ `--update` 时如果网页服务开着，Windows 上数据库会被锁住。脚本会提前提示先关服务。

## 项目结构

分四层，下面一层不认识上面一层。每一块都能单独 import 使用：

```
src/wowgear/      核心层：数据与规则，不依赖任何上层
  paths.py          所有路径的唯一来源
  const.py          职业 / 槽位 / 属性 / 中文名
  curve.py          属性曲线：装等 → 主属性 / 耐力 / 绿字的系数
  stats.py          单件装备换算成数值（三个桶各走一条曲线）
  source.py         装备从哪来（副本 / boss / 专业 / 套装）
  store.py          玩家自己填（自选属性、面板基准，按职业:专精分存）
  accounts.py       账号 / 登录令牌 / simc 历史 / 配装存档

src/wowlib/       业务层：解析、换算、一次配装会话
  simc.py           simc 字符串解析（文本 → 装备列表）
  calibrate.py      装备属性合计（含宝石附魔）
  stat_picker.py    属性由玩家选的装备（制造业 / 装绑）
  catalog.py        装备目录：查一件、列候选
  talents.py        天赋导入字符串解码（**尚未接入计算**，见待办）
  session.py        会话：穿上/预览/撤销/还原，把上面几块串起来

src/server/       HTTP 层：静态文件 + JSON 接口
src/web/          前端：index.html + css/ + js/ + img/

src/build/        构建期脚本，离线跑，不进运行时
  build_db.py           建库
  versions.py           数据集版本清单 + 过期检测
  fetch_static.py       从 Raidbots 拉装备/副本/赛季
  fetch_icons.py        批量下载图标（装备 / 宝石 / 附魔）
  fetch_gems_enchants.py 抓宝石与附魔数值
  fetch_sockets.py      抓装备插槽数量
  fetch_names.py        抽中文名
  fetch_class_base.py   抽裸装基础属性
  fetch_talents.py      抽天赋节点表（只有节点，没有效果）
  tiers.py / manage_items.py / icons.py / check_icons.py
```

**为什么分这么细**：`wowgear` 里不许 import 上层，出现 `import simc` 就说明分层破了，
会直接 ImportError——用报错把边界钉死。`build/` 和运行时分开放，是为了让人一眼看出
"改这个文件要不要重启服务"。

## 游戏内插件：在游戏里直接模拟换装

网页端算一件装备的属性是**估**——库里只存分配权重，靠 `curve.py` 那套按装等
采样的曲线反推真实数值。插件里是**读**：`C_Item.GetItemStats(link)` 返回游戏
自己算好的属性，战火升级、赛季提升、宝石加成全都在里面。所以 `curve.py`
那整套东西在插件里一行都用不上。

`addon/WoWGear` 现在是一个完整的配装模拟器，输入 `/wg` 打开：

- 左边 16 个部位（图标、装等、品质色），点一下选中
- 右边两个标签页：**我的装备**（背包 + 身上）和**装备库**（本赛季 1355 件可获得装备，带搜索）
- 装备库里的任何一件都能挑来模拟——这是"规划"和"比对"的区别：
  只比背包里有的，玩家自己换一下就知道结果了
- 搜索支持装备名 / 副本名 / 拼音 / 物品 ID。中文输入法没确认候选词时
  `GetText()` 给的是拼音串（`a'man'ni`），所以拼音也建了索引——
  `amanni`、`amn`、汉字，怎么打都能搜到；搜不到时会提示其他部位有几件
- 选中候选后点「改造」，可以给这件装备配**自选属性**（制造业那两条）、
  **宝石**、**附魔**、**打孔**，属性实时重算
- 左键候选立刻模拟，属性条实时显示换完之后四项绿字变成多少
- 可以连着换好几件叠加，随时「还原全部」

有个反直觉的事实决定了界面长什么样：**同部位装备的总属性完全相同**
（暴雪预算制，每件头盔都是 主属性 5259 / 绿字 7000 / 耐力 7889），
差别只在配比。所以"按总量排序"永远得 0，右栏改成四个按钮
——点哪条就按哪条排。插件算不出 DPS，就没资格替你决定堆什么。

模拟只算差值：`新百分比 = 面板百分比 + (曲线(新评级) - 曲线(旧评级))`。
面板值本身多准，结果就多准，天赋基线在这条式子里一减就抵消了。

**它算不出 DPS**——没有战斗模拟就没有 DPS，所以不给你"DPS 提升 3.2%"这种
数字（编一个比不给更坑，玩家会照着选）。真正算 DPS 还是要回网页端，
插件里那个「导出数据」按钮就是干这个的。

详见 `addon/WoWGear/README.md`。

## 一个属性数字怎么来的

```
simc 文本 → 装备对象 → alloc 万分比 → 单件数值 → 全身合计 → 面板显示
            解析        存库          曲线换算     加宝石附魔    加 base
```

四个关键设计，每条都踩过坑：

- **属性存比例不存数值**。`item_stats.alloc` 是万分比权重，一件装备只存一行就能算出它在
  任意装等下的属性。所以 341 / 344 这种轨道表里没有的装等也能直接算。
- **三条曲线，五类部位**。主属性、耐力、绿字是三条完全不同的曲线；颈/戒指/饰品因为没有
  主属性，绿字预算是独立一档（是腕/背的 1.42 倍）。拿主属性系数硬算绿字，331 装等会高估 22%。
- **状态存服务端，前端只发指令**。预览和结算走同一个函数，否则界面显示 +64 实际 +40，
  这种错不报异常，只会让人做错决定。
- **不确定的要标出来，不要静默兜底**。未收录的附魔写"没收录，本地没算它"，职业基础标
  "未含天赋"，按系数推算的附魔标"按系数推算"。宁可让人看到缺一块，也不给一个看起来很完整的错数字。

曲线表、宝石附魔的取数过程、套装转化、自选槽、面板口径，见 [`docs/计算.md`](docs/计算.md)。

装备主数据不用 KeystoneLoot 是因为它缺地下堡和制造业；Raidbots 那套有
`Delves Season 2`、`Prey Season 2`、`Epic Profession Items`，覆盖更全。

只留当前赛季的筛选逻辑、`expansion` 那个坑（老副本复刻）、表结构和图标链，见
[`docs/数据.md`](docs/数据.md)。

## 已知待办

- **天赋加成没进计算**。`panel.json` 的 base 是「面板 − 装备」，天赋那部分已经含在里面；
  但**没填面板的人**只拿到 `class_base`（职业+等级），天赋那截是空的，会比游戏低一截。

  这里还断着一条链：`talents.json` 只有节点表（点了什么），**没有效果表**（给多少属性），
  所以 `wowlib/talents.py` 能解出天赋但算不出加成，`session.py` 也就没接它。
  要走通得先解决效果数据从哪来——wowhead 的 spell 接口给不出 aura 108 的数值，
  DBC 的 `EffectPointsMin` 全是 0。绕一圈可能又回到"用面板反推"这个已有答案。
- **专精精通系数只验证了 2 个**。40 个专精里只有兽王/射击用真实面板核过，见
  `docs/专精精通系数表.md`。其中织雾武僧 `31.185` 明显是错的量级（同一条法术里还有 `0.31185`，
  差 100 倍），得拿武僧实际面板定夺。
- **副本与 BOSS 名还是英文**。装备/宝石/附魔的中文名都补上了，但来源行还是
  `The Venomous Abyss · Nek'zali the Soulcoiler`，要中文化得另做映射。
- **套装加成**。`item_set_bonus` 表已有但没算进属性。注意套装效果大多是伤害 proc，
  本身不改面板；真正缺的是"凑齐 2/4 件"这件事在界面上看不见。
- **属性权重与评分**。有了权重才能给"这套配装值多少分"，现在是纯手动比较。
- **附魔品质**。DBC 里同一附魔只有一套系数（对应 Tier2 / 580 卷轴），Tier3 卷轴（595）
  没有独立 id，所以用满级附魔的角色会低一点。SimC / Raidbots 也是这个行为，跟着它走
  能保证两边数字一致。
- **腿部附魔的数值是推算的**。护甲片/魔线这 6 条没有 wowhead 原文可抓，按客户端系数 ×
  580 档基数算出来，卡片上写明了"按系数推算"，需要游戏内核对一次。
- **其余未收录的附魔**。`enchants` 表只有本赛季 44 条，旧版本和采集工具附魔会标
  "没收录，本地属性里没算它"，不会静默算成 0。
- **插槽数靠抓取 + 保底规则**。`fetch_sockets.py` 抓的只有戒指和项链（这个版本只有这两个
  部位出厂带孔）。头/腰/腕的打孔器孔由玩家在界面上勾选（每件限一个）；少数团本项链的第二孔
  靠「simc 里已经插了宝石就算有孔」补上。
- **打孔器的孔写不进 simc**。SimC 没有 `sockets=` 选项，导出时会在弹层里点名提示，
  Raidbots 那边会少算这个孔里的宝石。

优先级判断标准只有一个：**会不会让人做出错误决定**。会误导的排前面，锦上添花的排后面。

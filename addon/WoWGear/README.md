# WoWGear 配装模拟

在游戏里直接对比装备、模拟换装后的面板变化。输入 `/wg` 打开。

![界面布局](#) <!-- 见下方"界面"一节的文字说明 -->

## 为什么搬进游戏里

网页版算一件装备的属性是**估**：数据库里只存了属性分配权重（alloc，万分比），
要靠 `src/wowgear/curve.py` 那套按装等采样的曲线表反推实际数值。整套
`curve.py`（五类部位 × 三条曲线 × 插值 + 外推）存在的唯一原因，就是
python 端拿不到客户端里那件装备的真实数值。

插件里不用估，直接读：

```lua
C_Item.GetItemStats(itemLink)   -- 返回这件装备的属性表，游戏自己算好的
```

战火升级、泰坦、赛季装等提升、宝石加成全部已经算在里面。所以插件里
**没有任何曲线采样代码**，`curve.py` 一行都用不上。

## 换算怎么办

属性点数变成百分比需要曲线斜率（每多少评级给 1%），这个 API 不给，
必须写表（`Data.lua` 的 `NS.CURVE`，DBC `__combat_ratings` 的 90 级列）。

但凡是跟"这个角色"有关的，一律不问表，运行时问游戏：

| 要算的东西 | 游戏给的 API |
|---|---|
| 当前百分比 | `GetCritChance()` / `GetHaste()` / `GetMasteryEffect()` / 全能评级加成 |
| 每 1% 要多少评级 | `GetCombatRating / GetCombatRatingBonus`（未进递减时精确） |
| 精通系数 | `GetMasteryEffect() / GetMastery()` |

最后一条值得单说。`spec_mastery` 表里有几个数一直存疑：织雾武僧 31.185
差了 100 倍、守护德 0.7 还是 1.0 说不清。插件里这两个数一除就是答案，
不用猜，也不用等验证——游戏当场算给你看。

## 模拟只算差值

```
新百分比 = 面板百分比 + (曲线(新评级) - 曲线(旧评级))
```

面板值本身多准，结果就多准。天赋基线（`spec_stats` 那张表）在这条式子里
是个加在末尾的常数，一减就抵消了——所以插件不需要基线表，换天赋、换版本、
换角色都不用重新标定。

左栏 16 个部位排两列，点一下选中；右栏列出这个部位的候选（**身上那件
也在里面**，点它等于还原）；左键候选即刻模拟，右键取消该部位的模拟。

模拟可以叠加：连换五件，属性条显示的是五件都换完的结果，随时「还原全部」。

## 它算什么，不算什么

**能算准的**

- 四项绿字的评级变化 → 百分比变化（含递减）
- 主属性、耐力点数变化
- 平均装等变化
- 双手武器顶掉副手（会一起扣掉副手属性，不然结果显示成白赚）

**算不了的**

- **DPS**。没有战斗模拟就没有 DPS，列表里那列「绿字总量」是四项点数直接
  相加，只用来粗筛。猜一个 DPS 数字给玩家看是最危险的做法。
- **套装效果、饰品特效、武器 dps**。`GetItemStats` 只有属性表。
- **宝石跟着装备走**。换装时宝石不会自动跟过去，候选按它自己当前的样子算
  （包里那件有孔没镶就是没镶）。

## 已知限制

- 换算表是 90 级的。角色等级不是 90 时界面会标红提示，结果不可信。
- 物品第一次见到时客户端可能还没数据，会显示「读取中…」，
  等服务器响应完自动刷新（监听 `ITEM_DATA_LOAD_RESULT`）。
- `Data.lua` 里 `NS.SLOT_TEX` 用的是游戏自己的角色面板贴图。如果某个部位
  显示成绿方块，说明那个贴图名在这版客户端改了，改 `NS.SLOTS[i].tex` 即可。

## 文件

| 文件 | 干什么 |
|---|---|
| `Data.lua` | 静态表：槽位、评级索引、换算曲线、专精精通系数 |
| `Util.lua` | 格式化、物品读取缓存（全部按 link 查，不用 itemID） |
| `Gear.lua` | 采集身上 16 槽 + 扫背包 + 判断能进哪个槽 |
| `Calc.lua` | 递减折算、百分比换算、换装模拟 |
| `UI.lua` | 主窗口骨架、属性条、底栏 |
| `List.lua` | 左栏部位网格、右栏候选列表 |
| `Export.lua` | 导出到网页端（`key=value` 一行） |
| `Core.lua` | 事件、节流刷新、斜杠命令 |

## 测试

```bash
python tests/test_addon_lua.py
```

用 lupa 起一个 Lua 5.1 环境（跟客户端同版本），灌一套假 API，真跑算法和
界面刷新。其中最关键的一项是「已知答案」：项目之前用两张游戏截图做过
受控实验，生存猎暴击 1033→1084（+51 评级）面板涨 1.11%，插件必须算出同一个数。

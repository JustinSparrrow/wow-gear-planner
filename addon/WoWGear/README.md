# WoWGear 数据导出（游戏内插件）

一个小插件，把当前角色的**评级、换算百分比、面板总数**一键导出成一行文本，
粘到配装规划器里，自动补上这个专精的基线数据。

## 它解决什么问题

规划器算绿字百分比需要一个数：**这个专精的天赋和被动一共给了多少**。

比如猎人暴击面板 38.15%，装备只贡献 23.15%，剩下的 15% 是天赋。
这 15% 只有游戏里知道——以前靠手动抄面板再手算，麻烦且容易抄错。

装上这个插件，切个专精点一下，四维全导出来，不用算。

## 它不做什么

**不做换装计算**。插件拿不到全部装备数据库（客户端只缓存你见过的物品），
也不能联网，「换上那件会变成什么样」还得在网页端算。

它是**数据采集器**，不是替代品。

## 这版验证到什么程度

**说实话：没有在真机游戏里跑过。** 写它的人手上没有能跑 12.1.5 的环境。
所以下面这些是「已经验过的」，和「只能靠你进游戏才能发现」的分开列：

已经验过：

- **语法**：用 Lua 运行时光真正编译过（`lupa`，Lua 5.5 编译器），不是数 `end` 那种糊弄
- **取值逻辑**：灌一套假 API（`GetCombatRating` 返回真实面板值）跑通 `collect()`，
  输出字段完整、数字格式正确、中文专精名不乱码
- **两端对拍**：把插件吐出来的串直接喂给 `src/wowlib/addon.py`，
  评级和面板都能解出来，字段名一个不差

只能进游戏才知道的：

- **战斗评级索引对不对**。这是最大风险点。代码优先读 `CR_MASTERY` 这类全局常量，
  读不到才用写死的数字（`mastery=26` 等）。但如果这个版本把常量也清了、编号又挪了，
  就会全部读成 0。
- **界面长得对不对**。输入框是 `BackdropTemplate` 自己画的（`InputBoxTemplate` 撑不住多行），
  边框和排版只能靠眼睛看。

**所以内置了一个自检**：如果七个评级一个都没读到，框下面会用红字写
「评级一个都没读到——这版游戏的战斗评级编号可能变了，这份数据不能用」。
看到这行就别往下走，把截图发我，改一行数字的事。

## 安装

1. 把 `WoWGear` 整个文件夹放进：
   ```
   World of Warcraft/_retail_/Interface/AddOns/WoWGear
   ```
   最终路径要能看到 `WoWGear.toc` 和 `Core.lua` 两个文件。

2. 重启游戏（或 `/reload`），角色选择界面点「插件」，确认 `WoWGear 数据导出` 已勾选。

3. 如果提示「插件已过期」：说明 `.toc` 里的 `## Interface` 版本号比当前客户端低。
   勾选「加载过期插件」即可，功能不受影响。

## 用法

游戏里输入 `/wg`（或 `/wowgear`），弹出一个框，里面就是数据。

框里会自动全选，`Ctrl+C` 复制，粘到规划器的「导入」框里。

## 导出前请注意

**脱战、清掉临时 buff 再导。**

插件读的是 `UnitStat()` 和 `GetCombatRating()` 的实时值，食物、合剂、
团队增益都会被算进去，导出来的基线就是虚高的。这个坑很隐蔽——
数据看着正常，但写进表里会让所有人的计算偏掉。

正确的做法：站主城、脱战、等 buff 过期（或者干脆刚上线就导）。

## 导出的是什么

一行 `key=value;key=value`，方便粘贴也方便人眼看。主要字段：

| 字段 | 含义 |
|---|---|
| `classKey` / `specKey` | 职业和专精，如 `hunter` / `survival` |
| `critR` 等 | 评级（`R` = rating） |
| `critB` 等 | 评级换算出的百分比（`B` = bonus），不含天赋 |
| `critT` / `hasteT` / `mastT` | 面板上显示的总数（`T` = total），含天赋 |
| `mastPts` | 精通点数（不是百分比，面板值 = 点数 × 专精系数） |

**为什么三样都要**：`T − B` 就是天赋那部分。只给其中一个，规划器算不出来。

## 数据怎么回到项目里

粘给维护者，或者自己跑：

```bash
python tools/import_addon.py "v=1;class=3;..."
python tools/import_addon.py "..." --write     # 校验通过后写进 spec_stats.json
```

工具会先拿插件给的换算值和项目自己的公式对一遍，**对不上就拒绝写入**。
因为那说明换算曲线和当前版本不一致，把反推出来的基线写进去等于固化错误。

## 已知待确认

全能（`vers`）的分母有疑问：客户端表写的是 54，但实测数据按 64 算基线更干净
（348 评级：54 → 基线 −1.00，64 → 基线 0.00）。插件导出真实数据后可以定案。

对不上时用 `--vers <面板值>` 手动指定，工具会把两种分母都试给你看。

# WoWGear 配装模拟

在游戏里直接对比装备、模拟换装后的面板变化。输入 `/wg` 打开。

![界面布局](#) <!-- 见下方"界面"一节的文字说明 -->

## 为什么搬进游戏里

网页版算一件装备的属性是**估**：数据库里只存了属性分配权重（alloc，万分比），
要靠 `src/wowgear/curve.py` 那套按装等采样的曲线表反推实际数值。整套
`curve.py`（五类部位 × 三条曲线 × 插值 + 外推）存在的唯一原因，就是
python 端拿不到客户端里那件装备的真实数值。

插件里不用估，直接读：

```lua
C_Item.GetItemStats(itemLink)   -- 返回这件装备的属性表，游戏自己算好的
```

战火升级、泰坦、赛季装等提升、宝石加成全部已经算在里面。所以插件里
**没有任何曲线采样代码**，`curve.py` 一行都用不上。

## 换算怎么办

属性点数变成百分比需要曲线斜率（每多少评级给 1%），这个 API 不给，
必须写表（`Data.lua` 的 `NS.CURVE`，DBC `__combat_ratings` 的 90 级列）。

但凡是跟"这个角色"有关的，一律不问表，运行时问游戏：

| 要算的东西 | 游戏给的 API |
|---|---|
| 当前百分比 | `GetCritChance()` / `GetHaste()` / `GetMasteryEffect()` / 全能评级加成 |
| 每 1% 要多少评级 | `GetCombatRating / GetCombatRatingBonus`（未进递减时精确） |
| 精通系数 | `GetMasteryEffect() / GetMastery()` |

最后一条值得单说。`spec_mastery` 表里有几个数一直存疑：织雾武僧 31.185
差了 100 倍、守护德 0.7 还是 1.0 说不清。插件里这两个数一除就是答案，
不用猜，也不用等验证——游戏当场算给你看。

## 模拟只算差值

```
新百分比 = 面板百分比 + (曲线(新评级) - 曲线(旧评级))
```

面板值本身多准，结果就多准。天赋基线（`spec_stats` 那张表）在这条式子里
是个加在末尾的常数，一减就抵消了——所以插件不需要基线表，换天赋、换版本、
换角色都不用重新标定。

左栏 16 个部位排两列，点一下选中；右栏列出这个部位的候选（**身上那件

模拟可以叠加：连换五件，属性条显示的是五件都换完的结果，随时「还原全部」。

## 装备库：规划的核心

只比背包里有的东西，玩家自己在游戏里换一下就知道结果了，插件没有意义。
**规划要回答的是"我还没有的那件值不值得去刷"**，所以右栏有两个标签页：

- **我的装备** —— 背包 + 身上那件，属性是客户端给的真值
- **装备库** —— 本赛季 1355 件可获得的装备（旧赛季刷不到了，不导），
  带搜索框，可以挑任何一件来模拟

数据来自 `data/wowgear.db`，由 `src/build/export_addon_lib.py` 导出成 `Lib.lua`。
换赛季要重新导一次；要连旧赛季一起导（约 3570 件）加 `--all`。

`Lib.lua` 是一行一件的紧凑文本，不是 Lua 表构造式——后者 3572 件要 462KB，
其中大半是 `[32]=`、`},` 这类语法噪音和被重复几千遍的掉落来源（实际只有
99 个唯一值）。改成紧凑文本 + 去重索引后 117KB，`Curve.lua` 加载时解析一遍，
1355 行耗时约 12ms。

### 为什么装等要统一折算

库里各赛季的基础装等是混的（59 / 108 / 197 / 298 都躺在一张表里），
跟玩家身上的 334 不是一个体系。各按各的装等比，结论必然是"装等低的更差"——
这是废话。所以**所有候选都按角色当前平均装等折算**，比的就只剩属性配比。

代价是丢了"这件装等更高"的信息，所以列表里仍然显示物品自身的参考装等，
右栏标题也写着"按 334 装等折算"。

### 为什么不能按"绿字总量"排序

查过全库的分配权重，一个反直觉但很关键的事实：

> **同部位的每件装备，总属性完全相同。**
> 护甲恒定 主属性 5259 / 绿字 7000 / 耐力 7889，一件头和另一件头的总预算一样。

这是暴雪的预算制设计——装备之间不比总量，只比**配比**：这件给暴击精通，
那件给急速全能。所以"按总量排序"永远得到 0，等于没排。

那插件凭什么替你决定哪个属性好？算不出 DPS 就没有资格决定。所以右栏
给了四个按钮：**点哪条就按哪条排**，右侧数字也是那条属性的差值。
你的专精该堆什么，你比插件清楚。

### 关于法系武器的一个坑

库里法系武器的主属性权重是 30629 / 16132 / 23380，而所有护甲和物理武器
都是 5259——差了 5.8 倍，看着像抓数据时把法术强度也算进了智力。
不修的话法系职业会看到智力是物理武器 5.8 倍的锤子。导出时按 5259 归一化。

### 搜索能搜什么

一个框，匹配三样东西：

| 输入 | 例子 | 为什么 |
|---|---|---|
| 装备名 | `信徒的流丝罩袍` | 知道名字的时候最快 |
| 掉落来源 | `塞塔里斯神庙` | **玩家记得的是"去哪个本刷"，不是装备叫啥** |
| 拼音 / 首字母 | `amanni` / `amn` / `a'man'ni` | 中文输入法还没确认时，插件收到的就是拼音 |
| 物品 ID | `158366` | 从攻略站抄过来直接能搜 |

多个词用空格分开，要**全部命中**：`神庙 戒指` 能把范围缩到几件。

#### 为什么非要支持拼音

这是被真实行为逼出来的，不是锦上添花。

中文输入法在**候选词还没确认**的时候，EditBox 的 `GetText()` 返回的是
**拼音串**，音节用撇号分隔：

```
屏幕上显示：阿曼尼          ← 这是输入法画在输入框上面的预编辑文字
GetText()：a'man'ni        ← 插件只能拿到这个
```

也就是说插件根本收不到汉字，不是"不支持中文"。与其跟客户端的行为较劲，
不如让拼音本身就能搜：导出时给每件装备算好全拼和首字母
（`src/build/export_addon_lib.py` 用 pypinyin），搜索时一起参与匹配。

代价是 `Lib.lua` 从 117KB 涨到 162KB。换"怎么打都能搜到"，值。

搜索是按部位来的（右栏只列当前部位的候选）。如果这个部位没有，底部会说
"其他部位有：主手 1、背部 1"，不会让你对着一片空白猜是不是坏了。

**掉落来源是中文的。** 这是专门补的一步：`data/wowgear.db` 里存的来源是
英文（"Temple of Sethraliss · Galvazzt"），来自 Blizzard API，那边只有英文。
`src/build/fetch_instances.py` 从客户端 DB2 表（wago.tools，locale=zhCN）
抓副本和首领的中文名，导出时替换掉。

不补会怎样：搜「阿曼尼」一件都搜不到，而中文客户端里玩家看到的地名就是
「阿曼尼」。装备名有中文、来源没有，这个缺口在搜索上最刺眼。

> 一个坑：最早是按 `instance_id` 查中文名，结果出现
> `Ruby Life Pools`（红玉新生法池）→「奥尔高格」——奥尔高格是黑石铸造厂的首领。
> 原因是 `item_sources.encounter_id` 并不总等于 `JournalEncounter.ID`，
> 数据源不知道具体首领时会把副本本身填进 encounter 字段。
> 所以改成**按英文名对齐**（两份表按 ID 配对成"英文→中文"），
> 查不到就保持英文，宁可显示英文也不张冠李戴。

## 它算什么，不算什么

**能算准的**

- 四项绿字的评级变化 → 百分比变化（含递减）
- 主属性、耐力点数变化
- 平均装等变化
- 双手武器顶掉副手（会一起扣掉副手属性，不然结果显示成白赚）

**算不了的**

- **DPS**。没有战斗模拟就没有 DPS，列表里那列「绿字总量」是四项点数直接
  相加，只用来粗筛。猜一个 DPS 数字给玩家看是最危险的做法。
- **套装效果、饰品特效、武器 dps**。`GetItemStats` 只有属性表。
- **装备库的属性是折算值**。库里没有真实物品数据（客户端不认识没见过的物品），
  只能用分配权重 × 装等系数算。同一件装备按你的装等折算后是多少，
  和它在你包里实际是多少，可能有几点出入。
- **宝石跟着装备走**。换装时宝石不会自动跟过去，候选按它自己当前的样子算
  （包里那件有孔没镶就是没镶）。

## 已知限制

- 换算表是 90 级的。角色等级不是 90 时界面会标红提示，结果不可信。
- 物品第一次见到时客户端可能还没数据，会显示「读取中…」，
  等服务器响应完自动刷新（监听 `ITEM_DATA_LOAD_RESULT`）。
- `Data.lua` 里 `NS.SLOT_TEX` 用的是游戏自己的角色面板贴图。如果某个部位
  显示成绿方块，说明那个贴图名在这版客户端改了，改 `NS.SLOTS[i].tex` 即可。

## 出故障先跑 `/wgcheck`

`C_Item.GetItemStats` 这类 API 有个要命的脾气：**失败时不报错，只返回空表**。
表现是"面板数字正常，但换上装备毫无变化、所有候选差值都是 0"——
看起来像整个插件坏了，其实只挂了一个调用。

所以进游戏 3 秒后会自动自检，也可以用 `/wgcheck` 手动跑。三种输出：

| 输出 | 含义 | 怎么办 |
|---|---|---|
| 没有红字 | 一切正常 | — |
| `有 N/M 件读不到属性表（FAIL:…）` | 四种调用方式全失败 | 已自动退回用装备库折算 |
| `原始属性表 N 项：ITEM_MOD_XXX=1, …` | 拿到了表但 key 不认识 | 把这一行发出来，`NS.Item.modID` 要加映射 |

实测的 key 形态是 `ITEM_MOD_AGILITY_SHORT` 这种**常量名**（不是它的值，
中文客户端里 `_G[...]` 是"敏捷"这个字符串），所以映射用的是"找特征词"：
名字里含 AGILITY 就是敏捷。以后再变形态，改 `MOD_TOKENS` 那张表即可。

## 文件

| 文件 | 干什么 |
|---|---|
| `Data.lua` | 静态表：槽位、评级索引、换算曲线、专精精通系数 |
| `Util.lua` | 格式化、物品读取缓存（全部按 link 查，不用 itemID） |
| `Gear.lua` | 采集身上 16 槽 + 扫背包 + 判断能进哪个槽 |
| `Calc.lua` | 递减折算、百分比换算、换装模拟 |
| `UI.lua` | 主窗口骨架、属性条、底栏 |
| `List.lua` | 左栏部位网格、右栏候选列表 |
| `Lib.lua` | 装备库数据（自动生成，162KB / 1355 件，含拼音索引） |
| `Curve.lua` | 装等曲线（`curve.py` 的 Lua 版）+ 库物品取数 + 搜索 |
| `Export.lua` | 导出到网页端（`key=value` 一行） |
| `Core.lua` | 事件、节流刷新、斜杠命令 |

## 测试

```bash
python tests/test_addon_lua.py
```

用 lupa 起一个 Lua 5.1 环境（跟客户端同版本），灌一套假 API，真跑算法和
界面刷新。其中最关键的一项是「已知答案」：项目之前用两张游戏截图做过
受控实验，生存猎暴击 1033→1084（+51 评级）面板涨 1.11%，插件必须算出同一个数。
